## X01 — project migration

`electron/project-transfer.cjs` implements a movable folder package with
`manifest.json`, hashed `records.json`, resource counts, SHA-256 blobs and
explicit unavailable resources. It uses a fixed logical-table whitelist,
not a database file copy. `project-transfer-commands.cjs` captures the data
owner across native chooser waits; core-owner wrappers resolve permissions.
`ProjectTransferDialog.tsx` exposes selection, source-file/folder choices,
counts/hash/missing-resource preview and restore confirmation. Frontend
owner integrated the project menu and a data-root/project-keyed dialog.

Actual SQLite + temporary disk tests cover:

- PDFs/indexed text, annotations, conversations and editable analysis files
  restore with new project/entity IDs, owned paths and internal references.
- Repeated same-name restores preserve earlier files and create distinct
  project names/directories. Damaged blobs/records fail before target writes;
  a later SQL constraint failure rolls back records and new imported files.
- Source selection includes accessible persisted historical thread roots,
  including a real old-root/default-root divergence and a directory alias.
  The restored session can discover and continue writing its manuscript;
  the original source remains unchanged.
- Serialized Windows drive and UNC roots restore correctly on this macOS
  host. These are source-format fixtures, **not Windows hardware acceptance**.
- Missing/changed result files keep their full expected inventory/hash
  state. A changed PDF does not get paired with an old text index as ready.
- Owned review runs round-trip through the actual separate review SQLite
  schema, retaining PDF/log/manifest and remapped run pin/reference. Other
  data owners are excluded; legacy unknown owners are explicitly unavailable.
- V01 run snapshots/local full logs retain history while active states are
  interrupted/cancelled. Resource ownership, PID/lease/container/SSH cleanup,
  approvals, native bindings, cloud links/outbox/grants are not imported.
  Restoration provenance retains the original owner/run/checkout; the
  historical checkout is not relabeled as execution in the new directory.
- A standalone result and its based-on-result thread restore without
  disabling foreign keys: nullable thread linkage is filled only after its
  actual result exists. Omitting results leaves that optional link null.
- V02 reports and raw source bytes migrate with new local run/comparison
  IDs. Their original attached-run hash remains historical/stale rather than
  being silently replaced with proof of a new execution.

User content is selected, not DLP-filtered. Credential/configuration and
live-authorization exclusions are structural. Limits are 10,000 resource
references, 500 MiB of distinct blobs and 25 MiB of record JSON. Source files
come from disk; unsaved editor drafts require saving first. The package is
not a complete Git/installed-environment/remote-storage backup.

## V02 — explicit numerical comparison

`metric-comparison.cjs` and its command registrar accept a user-chosen UTF-8
CSV or flat JSON record array (2 MiB, 10,000 rows, 100 columns). Source bytes
are frozen behind a per-window/run token. The user confirms expected/actual
columns, metric labels, units, datasets and absolute tolerance. Units and
datasets must match; no discovery or conversion is inferred. Outcomes are
missing, incomparable, within and outside. No run/checkpoint status changes.

The first candidate's binary-float epsilon was rejected in review. Final
`decimal-comparison.cjs` uses exact bounded BigInt decimal arithmetic. Standard
JSON parsing first validates syntax; numeric value tokens are then preserved
as text so parsing cannot round scientific results. Fixed tolerance reaches
the actual component bridge as text. Examples verified by behavior tests:

| Inputs | Exact outcome |
| --- | --- |
| `10000000000000000 → 10000000000000002`, tolerance `1` | outside, difference `2` |
| JSON literals `1 → 1.0000000000000001`, tolerance `0` | outside, difference `1e-16` |
| `7e-1 → 8e-1`, tolerance `0.1` | within |
| threshold `10000000000000001` sent from the actual input component | same decimal string at bridge |
| unsupported exponent/precision | incomparable, not rounded into a pass |

The shared CSV parser was extracted unchanged to `shared/delimited.mjs`.
`src/data-analysis.ts` re-exports it; its old test loader imports the actual
shared parser. All existing behavior assertions, including the author's
new full-source analysis test, remain intact.

Saved file receipts bind the owner, source SHA, run-snapshot SHA, mapping and
complete exact-string outcomes. Source/run/computation changes retain stale
history. History listing is metadata-first; details are paged in the UI.
The actual panel requires confirmation, prevents duplicate saves, ignores
late returns after scope changes, refreshes stale snapshots, and exports JSON.
Its source is explicitly user-selected evidence, not proof that the run
produced it or that the paper was scientifically reproduced.
